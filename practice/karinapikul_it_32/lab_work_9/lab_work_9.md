# Практична робота № 9

## Завдання 1. Групування за одним стовпцем

Для підрахунку кількості продажів кожного абонемента використано `GROUP BY` та `COUNT(*)`.

```sql
SELECT membership_id, COUNT(*) AS sales_count
FROM membership_sales
GROUP BY membership_id;
```

**Результат:**

- Абонемент з ID 2 — 1 продаж.
- Абонемент з ID 3 — 3 продажі.
- Абонемент з ID 5 — 1 продаж.
- Абонемент з ID 6 — 1 продаж.

Кожен рядок відповідає окремому ID абонемента, який є в таблиці продажів. Абонементи без продажів не відображаються.

## Завдання 2. Групування з JOIN

Щоб замість ID показати назву абонемента, використано `LEFT JOIN`.

```sql
SELECT memberships.type, COUNT(membership_sales.id) AS sales_count
FROM memberships
LEFT JOIN membership_sales
    ON membership_sales.membership_id = memberships.id
GROUP BY memberships.id;
```

**Результат:**

| Назва абонемента | Кількість продажів |
|---|---:|
| Разовий | 0 |
| Тижневий | 1 |
| Місячний | 3 |
| Квартальний | 0 |
| Піврічний | 1 |
| Річний | 1 |
| Пробний | 0 |
| Тестовий | 0 |
| VIP | 0 |

`LEFT JOIN` зберігає всі абонементи, навіть якщо їх ще ніхто не придбав. `COUNT(membership_sales.id)` рахує лише реальні записи про продажі.

## Завдання 3. Додаткова агрегатна функція

До підрахунку продажів додано `AVG()`, яка обчислює середнє значення ціни абонемента.

```sql
SELECT memberships.type,
       COUNT(membership_sales.id) AS sales_count,
       AVG(memberships.price) AS average_price
FROM memberships
LEFT JOIN membership_sales
    ON membership_sales.membership_id = memberships.id
GROUP BY memberships.id;
```

**Результат:** для всіх абонементів значення `average_price` дорівнює `200.0`.

## Завдання 4. Групування за двома стовпцями

```sql
SELECT client_id, membership_id, COUNT(*) AS sales_count
FROM membership_sales
GROUP BY client_id, membership_id;
```

**Кількість рядків результату: 6.**

Кожен рядок відповідає унікальній комбінації клієнта й абонемента. Наприклад, клієнт з ID 2 має два різні абонементи, тому для нього утворюються дві групи. Кількість груп залежить від реально наявних комбінацій.

## Завдання 5. Неоднозначний стовпець у GROUP BY

```sql
SELECT client_id, membership_id, COUNT(*) AS sales_count
FROM membership_sales
GROUP BY client_id;
```

Запит було виконано двічі. Обидва рази отримано однаковий результат:

```text
2|2|2
3|3|1
4|5|1
5|6|1
6|3|1
```

Для клієнта з ID 2 є два продажі, пов’язані з різними абонементами, але запит показує лише один membership_id. SQLite дозволяє такий запит, проте значення стовпця, який не входить до GROUP BY і не обчислюється агрегатною функцією, не визначене однозначно. Навіть якщо два запуски дали однаковий результат, покладатися на це не можна.

Контрольні запитання

1. Чому краще групувати за первинним ключем таблиці-довідника, а не за текстовою назвою?

Первинний ключ є унікальним ідентифікатором. Назви можуть повторюватися або змінюватися, тому ключ надійніше використовувати для групування.

2. Які рядки можуть зникнути, якщо в завданні 2 замінити LEFT JOIN на INNER JOIN?

Зникнуть абонементи, для яких немає жодного продажу. INNER JOIN залишає тільки рядки, для яких є відповідність у двох таблицях.

3. Звідки взялося значення додаткового стовпця в завданні 5 і чому на нього не можна покладатися? Що зробив би PostgreSQL?

Значення membership_id взялося з одного із записів відповідної групи. Оскільки в групі можуть бути різні абонементи, це значення не описує всі записи. PostgreSQL зазвичай відхилить такий запит, бо membership_id не входить до GROUP BY і не використовується в агрегатній функції.
